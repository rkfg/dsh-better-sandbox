# @rkfg/dsh-sandbox-allowlist-ui

Раздел «Sandbox» в диалоге настроек: четыре поля (гранты на запись, закрытые от
чтения каталоги и файлы, запрещённые к изменению имена путей), чтение и правка
через штатный слой настроек харнесса. Правка применяется без перемонтирования
записей и без рестарта, значение сохраняется в `cordis.patch.yml` профиля.

## Состав

| Файл | Роль |
|---|---|
| `index.js` | единственная хостовая запись коробки (пустой сервис) |
| `client.js` | клиентская половина: слот `settings.section`, форма, запись через `ctx.remote.settings` |
| `cordis.patch.yml` | слой бандла: одна запись |

Пакет с `dsh.client` обязан иметь ровно одну запись загрузчика, поэтому UI живёт
отдельным пакетом, а не внутри `@rkfg/dsh-sandbox-allowlist`.

## Установка

Ставится вместе с хостовой коробкой: `./sandbox-allowlist-bundle-install.sh`
(или штатно — `dsh plugin --profile web add <package>`). Нужен рестарт профиля,
чтобы загрузчик увидел новую запись.

## Почему не собственный Remote API

Собственное `ctx.remote`-пространство имён клиенту недоступно: по
`cookbook/adding-a-remote-api.md` клиент обязан объявить в `inject` сервис
`remote.<namespace>`, а это пространство генерируется из артефактов `./typert` и
`./remote`, которых у рукописного JS-пакета нет. Поэтому форма читает
`ctx.remote.settings.describe()` (без аргументов) и пишет
`ctx.remote.settings.update('sandbox-allowlist', patch, revision)` — тот же путь,
что у встроенного диалога настроек.

## Model Experience

### Влияние на контекст модели

Косвенно, через `@rkfg/dsh-sandbox-allowlist`: сохранённые здесь списки определяют, какие
строки анонса правил попадают в контекст рантайма и какие пути дают отказ чтения.

#### Token effect

Zero-direct: сам раздел ничего не добавляет в контекст модели.

#### KV Cache effect

Independent: изменения конфига сбрасывают переиспользование только через смену
секции анонса в `@rkfg/dsh-sandbox-allowlist`, к этой коробке это не относится.

## Known Limitations and Deferred Work

- **Нет валидации пути перед сохранением** — проверка `sandboxGuard.validate` на
  хосте есть, но форма её не вызывает: путь, закрывающий сам харнесс, сохраняется и
  потом просто не применяется.
- **Только volatile-поля** — `denyDepth`, `denySkipDirs`, `denyScanTtlMs`,
  `maskFallback`, `readDenialSignature` на странице не показываются: они читаются
  провайдерами при конструировании и требуют рестарта.
- **Одно языковое оформление на выбор UI** — словарь зарегистрирован в `en` и `zh`,
  других харнесс не поддерживает.
