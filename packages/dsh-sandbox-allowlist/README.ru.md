# dsh-sandbox-allowlist

Бандл DSH: расширяет песочницу additional-корнями на запись, запрещает изменять
`.git` и закрывает от чтения каталоги и файлы с секретами. Работает в трёх
контурах: файловые инструменты (`ctx.fs`), команды через `bash` (bwrap), поиск
через упакованный ripgrep.

## Состав

| Модуль | Роль |
|---|---|
| `lib/allowlist.js` | сервис `sandboxAllowlist`: эффективные списки правил, файл состояния, маска mode 000 |
| `lib/fs.js` | провайдер `fs`: забор на запись + запрет чтения |
| `lib/runner.js` | провайдер `sandbox`: аргументы bwrap для команд |
| `lib/subprocess.js` | провайдер `subprocess`: оборачивает в bwrap только ripgrep (иначе `grep`/`glob` читают закрытое) |
| `lib/masks.js` | общие аргументы bwrap: их собирают и раннер, и обёртка ripgrep, расхождение = дыра |
| `lib/policy.js` | канонизация путей, поиск защищённых каталогов с ограниченным обходом и кэшем |
| `lib/guard-api.js` | Remote-сервис `sandboxGuard`: `state` / `validate` / `add` / `remove` — правит списки на ходу |
| `lib/bundle.js` | группа записей бандла (`cordis.group`) |

`cordis.patch.yml` — слой бандла: гасит базовые `fs-sandbox`, `sandbox`,
`subprocess` и вставляет свои строки. Значения списков он не задаёт.

## Раздел настроек

Правила правятся в веб-UI: диалог настроек → раздел «Песочница» (четыре поля, по
строке на путь) → «Сохранить». Раздел приносит отдельный бандл
`dsh-sandbox-allowlist-ui`: пакет с клиентской половиной обязан иметь ровно одну
запись загрузчика, поэтому он не может жить внутри `dsh-sandbox-allowlist`.

Клиентский рукав регистрирует слот `settings.section` и работает через штатный
слой настроек: `ctx.remote.settings.describe()` (без аргументов, ответ —
`{ namespaces: [{ ns, value, revision, schema }] }`) и
`ctx.remote.settings.update('sandbox-allowlist', patch, revision)`. Хостовая
запись коробки — пустой сервис: вся логика в клиенте и в слое настроек.

Собственного `ctx.remote`-пространства имён у клиента сознательно нет: по
`cookbook/adding-a-remote-api.md` клиент обязан объявить в `inject` имя сервиса `remote.<namespace>`, а это
пространство появляется из генерируемых артефактов `./typert` и `./remote`, которых
у рукописного JS-пакента нет. Поэтому правка идёт через `ctx.remote.settings` —
тот же путь, которым пользуется сам диалог настроек.

Словарь раздела — `en` и `zh`: харнесс поддерживает только эти два языка, поэтому
подписей на других языках в интерфейсе нет.

## Установка

```
./sandbox-allowlist-bundle-install.sh                  # профиль web
./sandbox-allowlist-bundle-install.sh --home DIR --profile ИМЯ
```

Скрипт кладёт обе коробки в `node_modules` профиля, дописывает их в
`dsh.profile.bundles` (с копией `package.json`) и проверяет синтаксис.

Штатный путь установки плагина — `dsh plugin --profile web add <package>`
(passthrough pnpm, см. `cli-help.md`). Скрипт существует потому, что коробки лежат
рядом с исходниками в workspace, требуют пиновки версий харнесса и пересоздания
нулёвок маски сразу после `rm -rf`. После
него — рестарт профиля: новую строку загрузчик в запущенный процесс не добавляет.

В профильном `cordis.patch.yml` остаётся только значения:

```yaml
- id: sandbox-allowlist
  name: dsh-sandbox-allowlist/allowlist
  config:
    writableDirs: ["/opt/go", "/home/you/.cache"]
    readDenyDirs: ["/home/you/.ssh", "/home/you/.aws"]
    readDenyFiles: ["/home/you/.npmrc", "/home/you/.netrc"]
```

## Правила

| Поле | Значение | Правка без рестарта |
|---|---|---|
| `writableDirs` | каталоги вне рабочей папки, куда разрешена запись | страница «Песочница» |
| `denySegments` | имена путей, запрещённые к изменению (`.git`) | страница «Песочница» |
| `readDenyDirs`, `readDenyFiles` | закрыто от чтения (маска mode 000) | страница «Песочница» |
| `denyDepth`, `denySkipDirs`, `denyScanTtlMs` | обход при поиске `.git` для bwrap | нет |
| `maskFallback`, `readDenialSignature` | поведение раннера | нет |

Все четыре списка помечены `.volatile()`: харнесс отдаёт их как ссылки `{ get() }`
(cosmokit), обновляет без перемонтирования записи, а значение сохраняется в
profile patch. Единственный источник правил — config строки `sandbox-allowlist`;
никакого файла состояния, который мог бы перекрыть profile patch, в плагине нет.

Программная правка — `settings.update('sandbox-allowlist', patch, revision)`
(так делает страница настроек). Звать её нужно вне стека активации записи:
редактор конфигурации берёт лок на `package.json` профиля, который стартовый
проход удерживает, и вызов из `apply()` упирается в таймаут блокировки.

## Что закрыто и где границы

- `.git`: чтение свободно (`status`, `log`, `diff`), запись → EROFS. Имя сегмента
  проверяется на любой глубине в `ctx.fs`; в bwrap — до `denyDepth`, глубже нужна
  правка `denyDepth`.
- Репозиторий, созданный внутри самой команды, закрыт начиная со следующей команды.
- `rm -rf` защищённого каталога требует эскалации.
- `danger-full-access` снимает защиту — это и есть штатный путь, когда файл нужен.
- Процессы вне песочницы не покрыты: MCP-серверы и git-интеграция харнесса через
  `ctx.subprocess` идут pass-through.
- git по SSH внутри песочницы не работает: `ssh` не читает `~/.ssh`. Варианты —
  эскалация, ssh-agent, вынесенный `known_hosts`.
- Маска — bind каталога/файла-нулёвки с режимом 000 → EACCES. `--tmpfs` не годится:
  запись в него «удаётся» и исчезает.
- Удаление каталога с маской: сначала `chmod 0755` на каталог, корень и нулёвку.
- Нулёвки маски лежат в папке плагина. Если их стерли во время работы (так делает
  переустановка пакета), `confine` не падает: наличие нулёвок проверяется перед
  каждой командой, маска восстанавливается сама, а до восстановления закрытые пути
  прячутся fallback'ом (`maskFallback`).

## Проверка

Всё внутри workspace, без эскалаций и без риска для рабочего профиля:

```
./sandbox-allowlist-check.sh                    # базовый контур: basetest/allowtest/webtest
DSH_BUNDLE=1 DSH_PROBE=driver ./sandbox-allowlist-webfull.sh   # полный веб-профиль с бандлом
```

Профили живут в `.dsh-test/` (свой `DSH_HOME`, свой порт). Копирование идёт из
исходников в тестовые профили; обратное направление затирает правки. Canary для
проверки чтения — `~/.ssh/secret.key`, созданные пользователем; прочие секретные
файлы для проверки не читаются.

## Model Experience

### Контекст запроса: анонс правил песочницы

#### What the model sees

Секция `sandbox:allowlist` добавляется к контексту рантайма сразу после секции
политики песочницы (`SANDBOX_POLICY`) и существует, только если хотя бы один список
не пуст и `announceInPrompt` включён. Текст строится по трём шаблонам:

##### Verbatim text for this field

```markdown
Additional write roots beyond the session workspace (workspace-write mode only): <список путей в кавычках, через запятую>.
Protected path names inside every writable root (workspace-write mode): <список имён в кавычках> — writing there is refused the same way as writing outside the workspace, so escalate once with sandbox_permissions and a justification when the user genuinely needs it.
Protected from reading (secrets and personal data): <каталоги и файлы в кавычках, через запятую> — reading their contents is refused for tools and denied inside sandboxed commands; escalate once with sandbox_permissions and a justification only when the user explicitly needs that file.
```

#### Token effect

Conditional. Строки присутствуют только при непустых списках: одна строка на каждое
непустое семейство правил, длина пропорциональна числу путей. Пустые списки дают
ноль токенов.

#### KV Cache effect

Append-only относительно политики песочницы: секция добавляется после уже
существующих строк контекста и не меняет их. Правка списков через слой настроек
заменяет содержимое секции на ходу, поэтому переиспользование префикса сбрасывается
от места этой секции и дальше; порядок строк внутри секции фиксирован
(корни → имена путей → чтение), поэтому неизменные списки дают идентичный текст.

### Отказ как текст модели

#### What the model sees

Косвенно, через `dsh-tool-fs` и `dsh-tool-bash`: отказ fence'а и refusal-сигнатура
раннера попадают в результат инструмента. Пакет поставляет текст причины отказа
чтения (`"<путь>" is protected from reading by the sandbox-allowlist policy`) и
дополняет диалект bwrap сигнатурой `permission denied`, чтобы bash показал
политический отказ с подсказкой об эскалации, а не системную ошибку.

#### Token effect

Zero-direct: пакет не добавляет текста в контекст, кроме уже учтённого выше.
Появление текста отказа зависит от действия модели и оплачивается как результат
инструмента.

#### KV Cache effect

Independent: сообщения об отказах принадлежат истории разговора, а не системному
префиксу, и не влияют на переиспользование последних.

## Known Limitations and Deferred Work

- **Глубина `.git` в bwrap ограничена `denyDepth`** — сегмент имени проверяется на
  любой глубине в `ctx.fs`, но в confinement только до `denyDepth`; глубже нужна
  правка поля, и это рестарт.
- **Landlock не выражает ни вычитание записи, ни запрет чтения подпути** — при
  выборе этого раннера `denySegments` и `readDeny*` не применяются, о чём пишется
  предупреждение; молчаливой имитации защиты нет.
- **Процессы вне песочницы не покрыты**: MCP-серверы и git-интеграция самого
  харнесса через `ctx.subprocess` идут pass-through и не должны ломаться.
- **git по SSH внутри песочницы неработоспособен**, пока `~/.ssh` закрыт от чтения:
  нужен эскалированный запуск, ssh-agent или вынесенный `known_hosts`.
- **Имена закрытых каталогов остаются видны** в списке родителя: маска подменяет
  точку mode 000, а не фильтрует каталог-родитель.
- **`dsh plugin add` не используется** установщиком: нужны пиновка версий и
  пересоздание нулёвок маски до рестарта.
