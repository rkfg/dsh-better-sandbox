# @rkfg/dsh-better-sandbox (русская версия)

Дополнительные правила песочницы для DeepSeek Harness: каталоги вне рабочей папки, куда разрешена запись; имена путей, запрещённые к изменению; пути, закрытые от чтения. Правила живые — страница настроек меняет их, и запущенная сессия подхватывает их без рестарта.

Первична английская версия — [README.md](README.md); здесь то же изложение в сокращении, подробности по коду — в README пакетов.

## Что добавляется

Штатная песочница разрешает один корень записи (`workspace-write`) плюс временные каталоги. Плагин добавляет:

- **гранты** — кэши и тулчейны (`~/.cache`, `~/.ccache`, `/opt/go`), которые можно разрешить, не переходя на `danger-full-access`;
- **запреты** — `.git` внутри каждого записываемого корня становится неизменяемым, а секретные пути (`~/.ssh`, `~/.npmrc`, смонтированные сетевые ресурсы) — нечитаемыми: инструменты получают честный `EACCES`, команды внутри песочницы — ту же ошибку и политический маркер, поэтому модель видит отказ, а не содержимое файлов;
- **узкую эскалацию** — в штатной лестнице всего две ступени (`workspace-write` и `danger-full-access`), поэтому отвергнутый `git commit` обязан просить доступ ко всей файловой системе. Плагин добавляет именованный уровень (`write-segment`): в карточке подтверждения написано это имя, а вызов выполняется с открытыми на запись защищёнными именами путей и без других изменений.

Всё держится на швах харнесса: провайдеры `fs`, `sandbox` и `subprocess` заменяются классами-наследниками, которые добавляют правила. Контейнера здесь нет.

## Как устроено

| Слой | Механизм | Что закрывает |
|---|---|---|
| fence файловой системы | наследник провайдера `fs-sandbox`: проверки `stat`, `lstat`, `listDir`, `readText`, `streamText`, `readBytes`, `readByteRange`, `watch` и всех записей | инструменты `read`, `write`, `edit` и любой другой доступ через `ctx.fs` |
| confinement процессов | наследник провайдера `sandbox-local`: вставляет свои `bwrap`-привязки после привязки рабочей папки | все команды `bash`/`pwsh`/терминала, проходящие через confine |
| маски чтения | привязка пустого каталога или файла с режимом 000 поверх защищённого пути → `EACCES` | чтение внутри команд; перед каждой командой стаб проверяется по типу и режиму и при необходимости пересоздаётся |
| fence поиска | обёртка запуска ripgrep с теми же аргументами bwrap | `glob`/`grep`, которые вызывают ripgrep через `ctx.subprocess` и никогда через `ctx.fs` |
| отчёт о неприменённой защите | каждая причина, по которой грант или маска не применены, сохраняется, сообщается модели и показывается на странице настроек | правило, которое молча перестало работать, — именно этого этот плагин допускать не должен |
| контекст модели | блок анонса правил | модель знает границы ещё до попытки |
| уровень эскалации | именованная ступень добавляется в таблицу «строже шире» и в enum `sandbox_permissions` инструментов `bash`, `pwsh`, `write`, `edit` | о чём модель может попросить и что получает один одобренный вызов |

Защищённое чтение отказывает закрыто: маска — настоящая точка монтирования с режимом `000`, а её стабы плагин проверяет по типу и режиму перед каждой командой и при расхождении пересоздаёт.

## Уровень эскалации

После отказа при `workspace-write` модель повторяет тот же вызов с параметром `sandbox_permissions`. Штатная лестница предлагает `workspace-write` (не шире) и `danger-full-access` (вся файловая система) — то есть коммит стоит пользователю карточки со словами «полный доступ» ради команды, которой нужен только `.git`. Плагин добавляет третью ступень, по умолчанию она называется `write-segment`:

```
Allow this operation with write-segment permissions: commit the fix
git add -A && git commit -m "fix the fence"
                                   [ Reject ] [ Allow once ]
```

Согласие выдаёт ровно то, что обещает имя: имена из `denySegments` становятся записываемыми, и только для этого вызова. Команда по-прежнему идёт под bwrap с тем же рубежом рабочей папки, с теми же грантами и с теми же масками чтения — контур ниже проверяет, что `git commit` под уровнем проходит, а `~/.ssh` и пути вне рабочей папки остаются закрыты. Имя уровня меняется полем `segmentLevel`; пустое значение убирает ступень из лестницы.

Чтение эскалации не подлежит: ни один инструмент не объявляет `sandbox_permissions` для `read`, `glob`, `grep`, поэтому закрытый от чтения путь открывается только сменой правила.

## Требования

- Linux с непривилегированными user namespaces и [bubblewrap](https://github.com/containers/bubblewrap) (`bwrap --version`).
- DeepSeek Harness `0.2.1-rc.2`. Версии зависимостей в обоих пакетах зафиксированы именно на неё: dist-tag `latest` у семейства `@deepseek-ai/*` указывает на старое `0.0.1-rc.1`, а плагин зависит от внутреннего поведения провайдеров, которое менялось между релизами.

## Установка

Оба пакета опубликованы в скоупе `@rkfg`: это личное расширение харнесса, а не пакет семейства `@deepseek-ai/*`, и скоуп подчёркивает это различие.

Из npm — оба пакета в профиль:

```bash
dsh plugin --profile web add @rkfg/dsh-better-sandbox @rkfg/dsh-better-sandbox-ui
```

Из GitHub. Репозиторий — воркспейс из двух пакетов, поэтому git-URL обязан указывать на нужный подпакет: установка корня репозитория поставила бы приватный пакет воркспейса и никакой плагин:

```bash
dsh plugin --profile web add "git+https://github.com/rkfg/dsh-better-sandbox.git#path:/packages/@rkfg/dsh-better-sandbox"
dsh plugin --profile web add "git+https://github.com/rkfg/dsh-better-sandbox.git#path:/packages/@rkfg/dsh-better-sandbox-ui"
```

Из рабочего дерева — с пересозданием заглушек маски и копией `package.json` профиля:

```bash
./scripts/install.sh --profile web
```

При установке из npm внутри запущенной сессии ждут две особенности. Pnpm держит содержательное хранилище в `~/.local/share/pnpm`, а этот путь вне рабочей папки, то есть команда, запущенная в песочнице, пишет туда не сможет: добавьте его в `writableDirs` либо выполняйте установку в обычном терминале. И харнесс не может прочитать `~/.npmrc`, пока плагин закрывает его от чтения, — поэтому приватный реестр тоже требует установки вне песочницы; публичные пакеты это не касается.

Значения правил лежат в `~/.dsh/profiles/web/cordis.patch.yml`. Состав строк плагина и отключение заменяемых базовых провайдеров объявлены в patch-слое бандла, поэтому в профиле только значения:

```yaml
- id: better-sandbox
  name: '@rkfg/dsh-better-sandbox/rules'
  config:
    writableDirs:
      - /opt/go
      - /home/you/.cache
    denySegments:
      - .git
    readDenyDirs:
      - /home/you/.ssh
      - /home/you/.aws
    readDenyFiles:
      - /home/you/.npmrc
      - /home/you/.netrc
    segmentLevel: write-segment
```

Рестарт профиля обязателен после добавления записей и после смены кода модулей. Правка списков и имени уровня рестарта не требует. В списках понимают `~` и `~/…` (`~user` не раскрывается); неприменимые правила плагин показывает в `rejected`, а правило на несуществующий путь помечается `missing`.

Релиз публикуется тегом: выставите одинаковый `version` в обоих пакетах и пометьте коммит тегом `v<version>` — тогда `publish.yml` прогонит контур, отвергнет тег, не совпадающий с манифестами, и опубликует оба пакета с provenance. Публикация идёт по OIDC, без npm-токена; доверенного издателя (пользователь `rkfg`, этот репозиторий, файл workflow `publish.yml`) заводят один раз на странице каждого пакета, и новому доверенному издателю нужно успеть совершить первую публикацию за два дня, иначе настройка утратит силу.

## Страница настроек

С установленным пакетом `@rkfg/dsh-better-sandbox-ui` в диалоге настроек появляется раздел **Sandbox**: четыре поля (по пути в строке) — гранты на запись, закрытые от чтения каталоги, закрытые файлы и запрещённые имена путей, плюс одно поле с именем уровня эскалации (пустое значение выключает уровень). Сохранение пишет в патч профиля через слой настроек харнесса, и работающая сессия переходит на новые правила сразу: убрали каталог — следующее обращение к нему свободно, вернули — следующее обращение отвергнуто; переименовали уровень — enum уже смонтированных инструментов перезаписывается без рестарта. Подписи раздела переведены на английский и китайский — два языка, которые поддерживает интерфейс харнесса.

## Проверка

```bash
./scripts/check.sh     # один драйвер против базовых провайдеров, затем против плагина
./scripts/webfull.sh   # изолированный веб-профиль: форма бандла, страница настроек, живая правка
```

`check.sh` собирает одноразовые профили в `.dsh-test/`, направляет туда `DSH_HOME` и прогоняет детерминированный драйвер: запись в разрешённый каталог обязана дать `WROTE`, запись в запрещённый каталог и в `.git` — `DENIED FS_SANDBOX_DENIED` или `Read-only file system`, чтения фикстурных секретов обязаны быть отвергнуты, а удаление заглушек маски во время прогона — восстановлено. Случаи с пометкой `(level)` проверяют уровень: та же запись в `.git` обязана пройти, `git commit` — завершиться успешно, а всё вне рабочей папки и секретные пути — остаться отвергнутыми; там же печатается enum `sandbox_permissions` смонтированных инструментов, где обязано быть имя уровня. До этого `check.sh` проверяет синтаксис, манифесты против patch-слоёв, YAML обоих patch-слоёв и язык текста в репозитории. `webfull.sh` поднимает настоящий веб-стек на своём порту и сообщает число проблем активации; ожидаемое число — ноль.

## Границы

Ознакомьтесь с ними, прежде чем полагаться на такую настройку: плагин сужает доступ агента, но не является контейнером.

- Команда с `danger-full-access` работает без песочницы, и ни одно правило в ней не держится — в том числе маски чтения, которые существуют только в смонтированном пространстве имён команды. Инструменты `read`, `glob` и `grep` остаются закрытыми и там, остального нет.
- Собственная git-интеграция харнесса и MCP-серверы идут мимо этих швов и сознательно не покрываются.
- bwrap применяет защищённые имена до `denyDepth` уровней и не спускается в `denySkipDirs`; fence файловой системы проверяет их на любой глубине. Репозиторий глубже этого уровня для файловых инструментов закрыт, а внутри команды — нет: обрыв обхода виден в отчёте скана, а нужные деревья добавляются в `denyScanRoots`.
- Защищённое имя, созданное несколько секунд назад, становится защищено для команд не сразу: `denyScanTtlMs` — срок годности скана; `0` означает пересканировать корни перед каждой командой вместо этого окна.
- Landlock не умеет вычитать запись из более широкого правила и запрещать чтение подпути, поэтому там `denySegments` и `readDeny*` не применяются — причина попадает в лог, на страницу настроек и в контекст модели вместо имитации защиты.
- Стабы маски проверяются (тип и режим) и пересоздаются перед каждой командой: привязка следует за источником, и подменённый стаб показал бы то, на что он указывает. Одного режима 000 мало — владелец стаба всегда вернёт себе запись, поэтому подмену именно обнаруживают. По той же причине папка плагина не должна лежать внутри рабочей папки: об этом пишет лог хоста.
- Правило на чтение закрывает чтение, но не запись: закрытый от чтения путь, который ещё и записываем, можно перезаписать, не читая его.
- Имена закрытых каталогов остаются видны в списке родительского каталога: маска подменяет точку монтирования, но не фильтрует родителя.
- `git` по SSH внутри команды в песочнице перестаёт работать, пока `~/.ssh` закрыт от чтения: воспользуйтесь `ssh-agent` или вынесенным `known_hosts`.
- Удаление защищённого каталога извне (эскалированной командой) не предотвращается.
- Чтение эскалации не подлежит: `read`, `glob` и `grep` не объявляют `sandbox_permissions`, поэтому закрытый от чтения путь открывается только сменой правила.
- Постоянный терминал или pwsh-сессия сохраняют confinement, полученный при запуске: уровень действует на один вызов, поэтому уже открытую оболочку его правила не затрагивают.
- Уровень расширяет словарь, который принадлежит харнессу: ступень вписывается в схемы инструментов при их монтировании и чинится по событию `tools/change`. Если после обновления харнесса имя уровня перестало появляться в карточке, начинать нужно с этого шва; именно поэтому версии зависимостей зафиксированы.
- Страница настроек подсвечивает красным непригодный синтаксис (относительный путь без `~/`, `~user`, правило на всю файловую систему, дубликат) и не даёт сохранить; отказ хоста — причину, по которой правило не применено, — она показывает отдельным списком, беря его из сервиса `sandboxGuard`.

## Связанные работы

Пакет [dsh-better-sandbox](https://www.npmjs.com/package/dsh-better-sandbox) от `developerdh` (MIT) решает пересекающуюся задачу и вышел раньше. У него шире охват: правила для команд (`allow` / `ask` / `deny` по шаблонам с разбором составных команд), шаблоны каталогов с масками и backend на Windows ACL. Здесь охват уже и глубже: запреты на чтение действуют **внутри** процессов, запущенных в песочнице (маски mode 000 в bwrap плюс обёртка ripgrep), защищённые имена путей проверяются на любой глубине в слое файловой системы, а путь Linux/bwrap ежедневно работает на реальной машине, а не в непроверенном backend. Их README прямо указывает, что правила чтения ограничивают файловые инструменты и не перехватывают shell-команды; здесь те же правила доходят до shell. Выбирайте по нужной половине: политика команд и Windows — там, принудительные запреты под bwrap — здесь.
