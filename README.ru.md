# @rkfg/dsh-better-sandbox (русская версия)

Дополнительные правила песочницы для DeepSeek Harness: каталоги вне рабочей папки, куда разрешена запись; имена путей, запрещённые к изменению; пути, закрытые от чтения. Правила живые — страница настроек меняет их, и запущенная сессия подхватывает их без рестарта.

Первична английская версия — [README.md](README.md); здесь то же изложение в сокращении, подробности по коду — в README пакетов.

## Что добавляется

Штатная песочница разрешает один корень записи (`workspace-write`) плюс временные каталоги. Плагин добавляет:

- **гранты** — кэши и тулчейны (`~/.cache`, `~/.ccache`, `/opt/go`), которые можно разрешить, не переходя на `danger-full-access`;
- **запреты** — `.git` внутри каждого записываемого корня становится неизменяемым, а секретные пути (`~/.ssh`, `~/.npmrc`, смонтированные сетевые ресурсы) — нечитаемыми: инструменты получают честный `EACCES`, команды внутри песочницы — ту же ошибку и политический маркер, поэтому модель видит отказ, а не содержимое файлов.

Всё держится на швах харнесса: провайдеры `fs`, `sandbox` и `subprocess` заменяются классами-наследниками, которые добавляют правила. Контейнера здесь нет.

## Как устроено

| Слой | Механизм | Что закрывает |
|---|---|---|
| fence файловой системы | наследник провайдера `fs-sandbox`: проверки `stat`, `listDir`, `readText`, `streamText`, `readBytes`, `readByteRange` и всех записей | инструменты `read`, `write`, `edit`, `glob`, `grep` и любой другой доступ через `ctx.fs` |
| confinement процессов | наследник провайдера `sandbox-local`: вставляет свои `bwrap`-привязки после привязки рабочей папки | все команды `bash`/`pwsh`/терминала, проходящие через confine |
| маски чтения | привязка пустого каталога или файла с режимом 000 поверх защищённого пути → `EACCES` | чтение внутри команд; маска пересоздаётся, если её удалили |
| fence поиска | обёртка запуска ripgrep с теми же аргументами bwrap | `glob`/`grep`, которые вызывают ripgrep |
| контекст модели | блок анонса правил | модель знает границы ещё до попытки |

Защищённое чтение отказывает закрыто: маска — настоящая точка монтирования с режимом `000`, и плагин восстанавливает её перед каждой командой, если что-то её удалило.

## Требования

- Linux с непривилегированными user namespaces и [bubblewrap](https://github.com/containers/bubblewrap) (`bwrap --version`).
- DeepSeek Harness `0.2.1-rc.2`. Версии зависимостей в обоих пакетах зафиксированы именно на неё: dist-tag `latest` у семейства `@deepseek-ai/*` указывает на старое `0.0.1-rc.1`, а плагин зависит от внутреннего поведения провайдеров, которое менялось между релизами.

## Установка

Оба пакета опубликованы в скоупе `@rkfg`: это личное расширение харнесса, а не пакет семейства `@deepseek-ai/*`, и скоуп подчёркивает это различие.

Из npm — оба пакета в профиль:

```bash
dsh plugin --profile web add @rkfg/dsh-better-sandbox @rkfg/dsh-better-sandbox-ui
```

Из GitHub. Репозиторий — воркспейс из двух пакетов, поэтому git-URL обязан указывать на нужный подпакет: установка корня репозитория поставила бы приватный пакет воркспейса и никакой плагин:

```bash
dsh plugin --profile web add "git+https://github.com/rkfg/dsh-better-sandbox.git#path:/packages/@rkfg/dsh-better-sandbox"
dsh plugin --profile web add "git+https://github.com/rkfg/dsh-better-sandbox.git#path:/packages/@rkfg/dsh-better-sandbox-ui"
```

Из рабочего дерева — с пересозданием заглушек маски и копией `package.json` профиля:

```bash
./scripts/install.sh --profile web
```

Значения правил лежат в `~/.dsh/profiles/web/cordis.patch.yml`. Состав строк плагина и отключение заменяемых базовых провайдеров объявлены в patch-слое бандла, поэтому в профиле только значения:

```yaml
- id: better-sandbox
  name: '@rkfg/dsh-better-sandbox/rules'
  config:
    writableDirs:
      - /opt/go
      - /home/you/.cache
    denySegments:
      - .git
    readDenyDirs:
      - /home/you/.ssh
      - /home/you/.aws
    readDenyFiles:
      - /home/you/.npmrc
      - /home/you/.netrc
```

Рестарт профиля обязателен после добавления записей и после смены кода модулей. Правка четырёх списков рестарта не требует. В списках понимают `~` и `~/…` (`~user` не раскрывается); неприменимые правила плагин показывает в `rejected`, а правило на несуществующий путь помечается `missing`.

## Страница настроек

С установленным пакетом `@rkfg/dsh-better-sandbox-ui` в диалоге настроек появляется раздел **Sandbox**: четыре поля (по пути в строке) — гранты на запись, закрытые от чтения каталоги, закрытые файлы и запрещённые имена путей. Сохранение пишет в патч профиля через слой настроек харнесса, и работающая сессия переходит на новые правила сразу: убрали каталог — следующее обращение к нему свободно, вернули — следующее обращение отвергнуто. Подписи раздела переведены на английский и китайский — два языка, которые поддерживает интерфейс харнесса.

## Проверка

```bash
./scripts/check.sh     # один драйвер против базовых провайдеров, затем против плагина
./scripts/webfull.sh   # изолированный веб-профиль: форма бандла, страница настроек, живая правка
```

`check.sh` собирает одноразовые профили в `.dsh-test/`, направляет туда `DSH_HOME` и прогоняет детерминированный драйвер: запись в разрешённый каталог обязана дать `WROTE`, запись в запрещённый каталог и в `.git` — `DENIED FS_SANDBOX_DENIED` или `Read-only file system`, чтения фикстурных секретов обязаны быть отвергнуты, а удаление заглушек маски во время прогона — восстановлено. До этого он проверяет синтаксис, манифесты против patch-слоёв, YAML обоих patch-слоёв и язык текста в репозитории. `webfull.sh` поднимает настоящий веб-стек на своём порту и сообщает число проблем активации; ожидаемое число — ноль.

## Границы

Ознакомьтесь с ними, прежде чем полагаться на такую настройку: плагин сужает доступ агента, но не является контейнером.

- Команда с `danger-full-access` работает без песочницы, правила к ней не применяются.
- Собственная git-интеграция харнесса и MCP-серверы идут мимо этих швов и сознательно не покрываются.
- bwrap применяет защищённые имена до `denyDepth` уровней; fence файловой системы проверяет их на любой глубине.
- Landlock не умеет вычитать запись из более широкого правила и запрещать чтение подпути, поэтому там `denySegments` и `readDeny*` не применяются — плагин пишет предупреждение вместо имитации защиты.
- Имена закрытых каталогов остаются видны в списке родительского каталога: маска подменяет точку монтирования, но не фильтрует родителя.
- `git` по SSH внутри команды в песочнице перестаёт работать, пока `~/.ssh` закрыт от чтения: воспользуйтесь `ssh-agent` или вынесенным `known_hosts`.
- Удаление защищённого каталога извне (эскалированной командой) не предотвращается.
- Страница настроек подсвечивает красным непригодный синтаксис (относительный путь без `~/`, `~user`, дубликат) и не даёт сохранить; существование пути она проверить не может, потому что у страницы нет канала к сервису плагина, — правило на несуществующий каталог принимается и бездействует, пока каталог не появится.

## Связанные работы

Пакет [dsh-better-sandbox](https://www.npmjs.com/package/dsh-better-sandbox) от `developerdh` (MIT) решает пересекающуюся задачу и вышел раньше. У него шире охват: правила для команд (`allow` / `ask` / `deny` по шаблонам с разбором составных команд), шаблоны каталогов с масками и backend на Windows ACL. Здесь охват уже и глубже: запреты на чтение действуют **внутри** процессов, запущенных в песочнице (маски mode 000 в bwrap плюс обёртка ripgrep), защищённые имена путей проверяются на любой глубине в слое файловой системы, а путь Linux/bwrap ежедневно работает на реальной машине, а не в непроверенном backend. Их README прямо указывает, что правила чтения ограничивают файловые инструменты и не перехватывают shell-команды; здесь те же правила доходят до shell. Выбирайте по нужной половине: политика команд и Windows — там, принудительные запреты под bwrap — здесь.
