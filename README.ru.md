# dsh-sandbox-allowlist (русская версия)

Дополнительные правила песочницы для DeepSeek Harness: каталоги вне рабочей папки, куда разрешена запись; имена путей, запрещённые к изменению; пути, закрытые от чтения. Правила живые — страница настроек меняет их, и запущенная сессия подхватывает их без рестарта.

Английская версия — [README.md](README.md), она первичная; здесь то же самое плюс подробности по коду в README пакетов.

## Что добавляется

Штатная песочница умеет один корень записи (`workspace-write`) плюс временные каталоги. Плагин добавляет:

- **гранты** — кэши и тулчейны (`~/.cache`, `~/.ccache`, `/opt/go`), не прибегая к `danger-full-access`;
- **запреты** — `.git` внутри каждого записываемого корня становится неизменяемым, а секретные пути (`~/.ssh`, `~/.npmrc`, смонтированные шары) — нечитаемыми: инструменты получают честный `EACCES`, команды внутри песочницы — ту же ошибку и политический маркер.

Всё держится на швах харнесса: провайдеры `fs`, `sandbox` и `subprocess` заменяются классами-наследниками, которые добавляют правила. Контейнера здесь нет.

## Как устроено

| Слой | Механизм | Что закрывает |
|---|---|---|
| fence файловой системы | наследник провайдера `fs-sandbox`: проверки `stat`, `listDir`, `readText`, `streamText`, `readBytes`, `readByteRange` и всех записей | инструменты `read`, `write`, `edit`, `glob`, `grep` и любой другой путь через `ctx.fs` |
| confinement процессов | наследник провайдера `sandbox-local`: вставляет свои `bwrap`-привязки после привязки workspace | каждая confine'енная команда `bash`/`pwsh`/терминала |
| маски чтения | привязка пустого каталога/файла с режимом 000 поверх защищённого пути → `EACCES` | чтение внутри команд; маска пересоздаётся, если её удалили |
| fence поиска | обёртка спавна ripgrep теми же аргументами bwrap | `glob`/`grep`, которые зовут ripgrep |
| контекст модели | блок анонса правил | модель знает границы до попытки |

## Требования

- Linux с непривилегированными user namespaces и `bwrap` (`bwrap --version`).
- DeepSeek Harness `0.2.1-rc.2`: версии зависимостей в обеих коробках запинены именно на неё, потому что dist-tag `latest` у семейства `@deepseek-ai/*` указывает на старое `0.0.1-rc.1`.

## Установка

```bash
dsh plugin --profile web add dsh-sandbox-allowlist dsh-sandbox-allowlist-ui
# или из рабочего дерева:
./scripts/install.sh --profile web
```

Значения правил — в `~/.dsh/profiles/web/cordis.patch.yml`. Состав строк и отключение заменяемых базовых провайдеров объявлены в patch-слое бандла, поэтому в профиле только значения:

```yaml
- id: sandbox-allowlist
  name: dsh-sandbox-allowlist/allowlist
  config:
    writableDirs:
      - /opt/go
      - /home/you/.cache
    denySegments:
      - .git
    readDenyDirs:
      - /home/you/.ssh
      - /home/you/.aws
    readDenyFiles:
      - /home/you/.npmrc
      - /home/you/.netrc
```

Рестарт профиля обязателен после добавления записей и после смены кода модулей. Правка четырёх списков рестарта не требует.

## Страница настроек

С установленной коробкой `dsh-sandbox-allowlist-ui` в диалоге настроек появляется раздел **Sandbox**: четыре поля (по пути в строке) — гранты на запись, закрытые от чтения каталоги, закрытые файлы, запрещённые имена путей. Сохранение пишет в патч профиля через слой настроек харнесса, и работающая сессия переходит на новые правила сразу. Интерфейс переведён на английский и китайский — две поддерживаемые языки харнесса.

## Проверка

```bash
./scripts/check.sh     # один драйвер против базовых провайдеров, затем против плагина
./scripts/webfull.sh   # изолированный веб-профиль: форма бандла, страница настроек, живая правка
```

Ожидаемый исход: `WROTE` в разрешённом каталоге, `DENIED FS_SANDBOX_DENIED` или `Read-only file system` в запрещённом и в `.git`, отказы на чтении фикстуных секретов, восстановление маски после её внешнего удаления; в веб-контуре — ноль проблем активации.

## Границы

- Команда с `danger-full-access` работает без песочницы, правила к ней не применяются.
- Собственная git-интеграция харнесса и MCP-серверы идут мимо этих швов и сознательно не покрываются.
- bwrap применяет защищённые имена до `denyDepth` уровней; fence файловой системы — на любой глубине.
- Landlock не умеет вычитать запись из более широкого правила и запрещать чтение подпути: там `denySegments` и `readDeny*` не применяются, о чём пишется предупреждение.
- Имена закрытых каталогов видны в списке родителя: маска подменяет точку монтирования, а не фильтрует каталог-родитель.
- `git` по SSH внутри команды перестаёт работать, пока `~/.ssh` закрыт от чтения: нужен `ssh-agent` или вынесенный `known_hosts`.
- Удаление защищённого каталога извне (эскалированной командой) не предотвращается.
